# 03 — 기능 상세 명세

## 1. 여행지 추천 기능

### 입력
- 필드: `destination`
- 타입: 문자열
- 필수: 예
- 권장 최대 길이: 100자
- 앞뒤 공백 제거 후 빈 문자열이면 요청하지 않는다.
- 현재는 여행지 텍스트 하나만 받는다.

### 처리 흐름
1. 사용자가 추천 버튼을 누른다.
2. 프런트엔드에서 빈 값과 길이를 검사한다.
3. 버튼을 비활성화하고 로딩 문구를 표시한다.
4. `POST /api/recommend`로 JSON 요청을 보낸다.
5. 서버에서 입력을 재검증하고 OpenAI API를 호출한다.
6. 서버에서 AI 응답 JSON 구조와 값의 개수를 검사한다.
7. 정상 응답이면 화면에 추천 2개와 예산 1개를 렌더링한다.
8. 실패하면 사용자 친화적인 오류 메시지를 표시한다.
9. 요청 종료 후 버튼을 다시 활성화한다.

## 2. AI 추천 규칙
AI에게 다음 규칙을 전달한다.
- 입력한 여행지와 분위기·활동·자연환경·문화 등에서 관련성이 있는 다른 여행지 2곳을 제안한다.
- 결과는 우선순위가 높은 순서로 반환한다.
- 원래 입력한 장소를 그대로 반복하지 않는다.
- 추천 이유는 구체적이고 짧은 한국어 문장으로 작성한다.
- 실재 여부가 불확실한 장소를 사실인 것처럼 생성하지 않는다.
- 최신 운영 정보, 가격, 영업시간, 교통편 등을 확인했다고 주장하지 않는다.
- 충분한 근거가 없으면 성공 응답 대신 `INSUFFICIENT_CONTEXT` 등 명시된 오류를 반환한다.
- 정확히 2개를 반환한다. 1개 또는 3개 이상이면 서버 검증에서 실패 처리한다.

## 3. 예산 추정 규칙
- 기본 가정: 1인 기준, 2박 3일, 현지 체류 중심, 항공 및 출발지-목적지 장거리 교통비 별도.
- 예산은 추정치이며 확정 견적이 아니다.
- 통화 코드를 포함한다(예: KRW, JPY, USD).
- 금액을 모르면 임의의 정밀한 숫자를 만들지 말고 추정 불가 상태를 반환한다.
- 예산에 포함되는 항목과 제외되는 항목을 구분한다.
- 사용자가 제공하지 않은 출발지·인원·여행 날짜를 알고 있는 것처럼 말하지 않는다.

## 4. 권장 성공 응답 스키마
```json
{
  "success": true,
  "data": {
    "destination": "제주도",
    "recommendations": [
      {
        "priority": 1,
        "name": "추천 여행지 A",
        "region": "국가 또는 지역",
        "reason": "추천 이유"
      },
      {
        "priority": 2,
        "name": "추천 여행지 B",
        "region": "국가 또는 지역",
        "reason": "추천 이유"
      }
    ],
    "budget": {
      "currency": "KRW",
      "min": 300000,
      "max": 500000,
      "assumptions": [
        "1인 기준",
        "2박 3일",
        "항공 및 장거리 교통비 제외"
      ],
      "included": ["현지 식비", "현지 이동", "숙박"],
      "excluded": ["항공권", "개인 쇼핑"],
      "disclaimer": "실제 비용은 날짜와 예약 조건에 따라 달라질 수 있습니다."
    }
  }
}
```
위 장소명과 금액은 스키마 설명용 예시이며 실제 추천 데이터로 사용하지 않는다.

## 5. 피드백 기능
### 작성
- 로그인 없이 작성 가능
- 필드: `content`
- 1~1000자
- 빈 문자열·공백만 있는 문자열 거부
- 성공 시 DB 저장 후 최신 목록 갱신
- 중복 클릭 방지를 위해 전송 중 버튼 비활성화

### 목록
- 최신순(`created_at DESC`)
- 화면 하단에 전체 목록 표시
- 각 항목은 작성 시각과 내용 표시
- 사용자 이름·이메일은 수집하지 않는다.
- 목록이 비어 있으면 안내 문구 표시
- 조회 실패 시 추천 기능과 피드백 작성 폼 전체를 중단하지 말고 목록 영역에 오류 표시

## 6. 우선순위 표현
- 1순위: `1순위 추천`
- 2순위: `2순위 추천`
- 우선순위는 서버에서 배열 순서와 priority 값을 검증한다.
- 프런트엔드에서 임의로 순위를 재계산하지 않는다.

## 7. 이미지 정책
현재 구현 범위에는 이미지 검색 API가 없다.
- AI가 `image_url`을 임의로 생성하도록 하지 않는다.
- 여행지 실제 사진을 가져온 것처럼 표시하지 않는다.
- 제공된 원본 사진은 분위기 참고용으로만 표시할 수 있다.
- 실제 장소별 사진이 반드시 필요해지는 경우 별도 이미지 공급자, 출처, 라이선스, 오류 대체 정책을 먼저 승인받아 명세를 변경한다.

## 8. 기능 완료 기준
- 입력한 여행지에 대해 추천 2개만 표시한다.
- 두 추천의 순위가 구분된다.
- 예산 카드에 통화·금액 범위·가정·포함/제외 항목이 표시된다.
- 잘못된 AI 응답은 사용자 화면에 그대로 노출되지 않는다.
- 비회원 피드백 저장 및 최신순 조회가 가능하다.
- 새 피드백 등록 직후 목록에서 확인할 수 있다.
