# 06 — 오류 처리, 테스트 및 Vercel 배포

## 1. 오류 처리 원칙
모든 오류는 사용자가 다음 행동을 이해할 수 있도록 짧은 한국어 메시지로 표시한다. 오류가 발생해도 페이지 전체가 멈추지 않도록 추천 영역과 피드백 영역의 상태를 독립적으로 관리한다.

## 2. 필수 상태
### 추천 영역
- 초기: 여행지를 입력하도록 안내
- 로딩: 추천 결과 생성 중 표시, 중복 요청 방지
- 성공: 여행지 카드 2개 + 예산 카드 1개 표시
- 입력 오류: 입력란 주변에 구체적 안내
- AI 오류: 재시도 안내
- 응답 형식 오류: 안전한 오류 안내

### 피드백 영역
- 목록 로딩
- 목록 성공
- 목록 빈 상태
- 목록 조회 오류
- 피드백 전송 중
- 전송 성공
- 전송 실패(입력 내용 유지)

## 3. 수동 테스트 체크리스트
### 추천
- [ ] 여행지 입력 없이 추천 버튼 클릭 → 요청하지 않고 안내
- [ ] 공백만 입력 → 요청하지 않고 안내
- [ ] 100자를 초과한 입력 → 요청하지 않고 안내
- [ ] 정상 여행지 입력 → 결과 3개 영역 표시
- [ ] 추천 결과가 정확히 2개인지 확인
- [ ] 1순위·2순위가 명확히 표시되는지 확인
- [ ] 예산 통화·범위·가정·포함/제외 항목 표시 확인
- [ ] 추천 요청 중 버튼 중복 클릭 방지
- [ ] OpenAI Key 누락 → 사용자에게 안전한 오류 표시
- [ ] OpenAI API 오류/시간 초과 → 재시도 가능한 오류 표시
- [ ] AI가 잘못된 JSON 반환 → 화면에 원문을 표시하지 않고 오류 처리

### 피드백
- [ ] 비회원 상태에서 작성·전송 가능
- [ ] 빈 피드백 전송 거부
- [ ] 1000자 초과 피드백 거부
- [ ] 정상 전송 후 Supabase에 행 생성
- [ ] 새 글이 목록 최상단에 표시
- [ ] 새로고침 후에도 글 유지
- [ ] DB 저장 실패 시 작성 내용 유지
- [ ] DB 조회 실패 시 목록 영역에 오류 표시
- [ ] `<script>` 등 HTML 문자열이 실행되지 않고 텍스트로 표시
- [ ] 전송 중 중복 제출 방지

### UI 및 보안
- [ ] 원본 이미지가 변경되지 않았는지 확인
- [ ] 이미지 전체가 잘리지 않고 비율 유지
- [ ] 모바일·태블릿·데스크톱 레이아웃 확인
- [ ] 키보드만으로 입력 및 버튼 실행 가능
- [ ] 브라우저 개발자 도구에서 비밀키가 보이지 않는지 확인
- [ ] `.env.local`이 Git에 포함되지 않는지 확인

## 4. API 테스트 예시
추천:
```bash
curl -X POST http://localhost:3000/api/recommend \
  -H "Content-Type: application/json" \
  -d '{"destination":"제주도"}'
```
피드백 저장:
```bash
curl -X POST http://localhost:3000/api/feedback \
  -H "Content-Type: application/json" \
  -d '{"content":"여행지 추천이 유용했어요."}'
```
피드백 목록:
```bash
curl http://localhost:3000/api/feedback-list
```
실제 로컬 포트는 실행 환경에 따라 달라질 수 있다.

## 5. Vercel 배포 절차
1. Git 저장소에 프로젝트를 커밋한다. 단, `.env.local`은 커밋하지 않는다.
2. Vercel에서 저장소를 Import한다.
3. 프로젝트의 환경변수에 다음 값을 등록한다.
   - `OPENAI_API_KEY`
   - `OPENAI_MODEL`
   - `SUPABASE_URL`
   - `SUPABASE_SERVICE_ROLE_KEY`
4. Node.js 런타임과 API 경로가 Vercel Functions 규칙에 맞는지 확인한다.
5. Build 설정은 프로젝트 구조에 맞게 지정한다. 정적 HTML 프로젝트에 불필요한 빌드 단계를 강제로 추가하지 않는다.
6. Deploy를 실행한다.
7. 배포 URL에서 추천·피드백 저장·목록 조회를 모두 테스트한다.
8. 실패 시 Vercel Function 로그에서 원인을 확인하되 비밀값이 출력되지 않도록 한다.

## 6. 완료 기준
- 체크리스트의 모든 필수 항목을 실제로 실행해 결과를 기록한다.
- Supabase DB 연동이 실제 배포 환경에서 확인된다.
- OpenAI 추천 API가 실제 배포 환경에서 확인된다.
- 오류 메시지가 정상적으로 노출된다.
- 비밀키가 클라이언트에 노출되지 않는다.
- Vercel 배포 URL에서 주요 사용자 흐름이 완료된다.
