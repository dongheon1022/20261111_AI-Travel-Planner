# 02 — UI 구현 지침

## 1. 디자인 기준 파일
기준 파일: `assets/reference-image.png`

- 원본 크기: 875 × 553 px
- 원본 비율: 약 1.582:1
- 이미지 특징: 푸른 하늘과 바다, 넓은 모래사장, 멀리 보이는 산, 필름 프레임 및 아날로그 필름 질감
- 이 파일은 사용자가 제공한 시각 기준이며, 원본을 변경하지 않는다.

**절대 금지:** 색상 보정, 크롭, 회전, 리사이즈하여 별도 파일로 저장, 필터, 오버레이, 프레임 제거, 요소 추가·삭제. 화면 표시 크기만 CSS로 조정하고 `object-fit: contain`을 사용한다. 원본 파일은 그대로 보존한다.

## 2. 화면 구성
페이지는 다음 순서로 구성한다.
1. Header: 서비스명 `AI Travel Planner`
2. Hero: 여행을 떠올리게 하는 짧은 문구와 원본 필름 이미지
3. Search: 여행지 입력과 추천 실행 버튼
4. Results: 추천 여행지 2개와 예산 1개, 총 3개 카드
5. Feedback: 로그인 없는 피드백 입력 폼
6. Feedback list: 최신순 피드백 목록

화면 구성은 단순하고 읽기 쉽게 만든다. 사용자가 제공하지 않은 별도 로고나 복잡한 브랜드 그래픽을 임의로 만들지 않는다.

## 3. 이미지 표시 규칙
```html
<img
  src="/assets/reference-image.png"
  alt="푸른 바다와 모래사장, 멀리 보이는 산이 담긴 필름 사진"
>
```
```css
.hero-image {
  display: block;
  width: 100%;
  height: auto;
  object-fit: contain;
}
```
이미지를 배경으로 강제 크롭하지 않는다. 작은 화면에서도 원본의 상하좌우가 잘리지 않게 한다. 추천 여행지 카드에 이 사진을 사용할 경우 실제 추천 장소의 사진이 아닌 분위기 참고 이미지임을 표시한다.

## 4. 레이아웃 가이드
- 전체 콘텐츠는 읽기 편한 최대 너비를 설정하고 가운데 정렬한다.
- 데스크톱: 결과 카드 3개를 한 행에 배치할 수 있다.
- 태블릿: 카드 2개 + 다음 줄 1개 또는 한 열 배치를 사용한다.
- 모바일: 카드와 입력 폼을 한 열로 쌓는다.
- 화면 폭이 좁을 때 가로 스크롤이 생기지 않도록 한다.
- 입력창과 버튼은 터치하기 충분한 높이를 확보한다.

## 5. 스타일 가이드
이미지의 차분한 바다·하늘 분위기와 어울리는 절제된 스타일을 사용한다.
- 기본 배경: 밝은 중성색
- 본문: 짙은 회색 또는 남색 계열
- 강조색: 이미지에서 영감을 받은 차분한 블루 계열
- 카드: 명확한 경계, 적절한 여백, 과도하지 않은 그림자
- 버튼: 기본/hover/focus/disabled 상태를 구분
- 폰트: 시스템 한글 폰트 우선, 별도 웹폰트 필수 아님

정확한 색상값·간격·타이포그래피를 이미지에서 추출했다고 주장하지 않는다. 이미지 외 UI 시안은 제공되지 않았으므로 위 원칙을 바탕으로 일관된 화면을 구현한다.

## 6. 결과 카드 구성
### 여행지 카드
- 순위 배지: `1순위 추천` 또는 `2순위 추천`
- 여행지 이름
- 국가/지역(응답에 있을 때)
- 추천 이유
- 사진이 실제 장소 이미지가 아니라면 `여행 분위기 참고 이미지` 표시

### 예산 카드
- 제목: `예상 여행 예산`
- 금액 또는 범위 + 통화
- 기본 가정: 1인, 2박 3일, 항공·장거리 교통비 별도
- 포함 항목 / 제외 항목
- 참고 추정치이며 실제 비용과 다를 수 있다는 안내

## 7. 접근성 및 상태
- 입력 요소에 label 제공
- 버튼은 키보드로 실행 가능해야 함
- focus 표시를 제거하지 않는다.
- 오류는 색상만으로 구분하지 말고 텍스트도 제공한다.
- 로딩 시 스크린리더가 상태를 알 수 있도록 `aria-live` 영역을 사용한다.
- 결과가 없을 때 빈 상태 문구를 제공한다.

## 8. UI 완료 기준
- 제공된 원본 이미지 파일이 그대로 사용된다.
- 이미지 비율이 유지되고 잘리지 않는다.
- 세 개의 결과 카드가 구분된다.
- 모바일 화면에서 입력·결과·피드백을 무리 없이 사용할 수 있다.
- 로딩·성공·오류·빈 상태가 각각 시각적으로 구분된다.
